# 《离开山谷以前》Demo 迭代计划

本计划以 `DESIGN_LOCK.md` 为唯一方向依据。目标不是在现有 Demo 上增加更多文字和按钮，而是逐步替换其错误的体验骨架。

## 0. 参考作品转化后的执行清单（2026-09-01）

参考方向不是复制某一款游戏，而是组合四种已验证的能力：

- 《The Star Named EOS》/《Behind the Frame》：手绘有限场景中的环视、取景与空间感。
- 《SEASON》：玩家自主决定什么值得拍，并在旅程后回看自己的记录。
- 《A Normal Lost Phone》/《Bury Me, My Love》：手机本身承载人物生活，消息按时间和行动推进。
- 《Firewatch》/《Open Roads》：移动过程中维持远程关系，让路途本身发生内容。

### P0 当前迭代：核心体验闭环

- [x] 鼠标位置控制有限视线，背景保持安全超扫范围。
- [x] 平静、行走、恢复三种呼吸状态。
- [x] 点击目的地后镜头转向目标并自动播放走近过程。
- [x] 手机壳、壁纸、消息、地图、相机、相册、时间和电量基础结构。
- [x] 相机可移动构图、变焦并将构图保存在相册。
- [x] 拍摄时将当前取景固化为独立 WebP 位图，后续不再依赖原背景重新裁切。
- [x] 相册照片可发送给联系人，照片进入真实消息线程。
- [x] 联系人根据当前地点和消息类型出现“正在输入”并回复。
- [x] 日期、时间、电量使用统一状态和可显式设置接口。
- [x] 把铁索、车辆和夜间光照遮罩纳入照片快照，不再只保存静态场景构图。
- [x] 增加版本化章节检查点和相册本地存储，标题页可以继续旅程。

验收：玩家能完成“看到景物 → 靠近 → 打开相机 → 自由构图 → 拍摄 → 相册回看 → 发给朋友 → 收到情境回复”的完整闭环。

### P1 冒险乐趣切片

- [x] 增加铁索与碎石坡两种轻量通过，不使用耐力条。

- [x] 验证低亮度底图、全局黑夜遮罩、手电/手机光和车辆独立层技术方案。

- [x] 让手机在行动中遗失，之后所有手机入口都明确表现为空口袋状态。
- [x] 车辆、两位救援者、车灯和动态物件全部保持独立资源层。

- [x] 两位救援者拥有独立视觉层，并通过先确认安全、递水、劝阻夜返的对话建立相处节奏。

- [x] 手机归还后恢复完整相册，离谷前必须回看玩家自己的照片才进入结尾。
- [x] 手机由清晨遛狗的普通路人归还，不加入灵异解释。
- [x] 信件只在高处短暂停留，并在离谷前的相册回看与结尾文案中形成余韵。

### 当前执行顺序

1. 当前 14 节点主线、地形、夜路、救援、寻机和结尾已经串通。
2. 分地点风声、林下衰减、车辆低频、脚步材质和三种呼吸声已经接入主线。
3. 新场景板与独立物件已统一转为 WebP，Pixi 渲染层延迟加载并按相邻场景预载。
4. 下一轮重点不是继续加剧情，而是从头到尾真人节奏试玩、低端设备测试，并据此校准夜路可读性和整体 35–50 分钟时长。

## 1. 当前 Demo 诊断

### 可以保留

- 第一人称视角
- 手机作为贯穿系统
- 拍下信件、丢失手机、归还后重看照片的结构
- Web 发布和低门槛试玩
- GPT Image 生成的山脊、森林、公路视觉基调
- 单线短篇的范围控制

### 必须替换

| 当前问题 | 修改目标 |
|---|---|
| 开场直接进入山脊 | 增加抵达、徒步、好奇心和人物建立，让它先成为一次旅行 |
| 三张背景反复调色使用 | 扩展到 12–14 张连续场景板，并拆分视差层 |
| 点击热点后瞬间换图 | 改为连续镜头推进、脚步、遮挡和镜头节奏转场 |
| 没有真正的冒险过程 | 加入观察路线、轻量通过、回望距离和自愿拍照 |
| 主角几乎没有身份 | 加入固定随身物、手机个性、相册、聊天和生活化声音；身体不入镜 |
| 信件被当成悬疑核心 | 降为 45 秒以内的偶然插曲，删除伪造预言和神秘化包装 |
| 危险通过剧情按钮突然发生 | 让时间随探索自然流逝，由玩家主动查看地图后完成认知翻转 |
| 夜林只有三个点击点 | 制作为 8–10 分钟可玩的寻路与自救段落 |
| 获救和找手机被压缩成面板 | 制作车内相处、共同返回、公路搜索和拨号的连续场景 |
| 陌生人只是剪影和一句台词 | 设计两位普通、可信、有互动节奏的新朋友 |
| 手机归还过于神秘化 | 使用普通环境、普通动作和停顿表现毫无预兆的归还 |
| 结局用文字直接解释主题 | 改为查看玩家自己的相册、想起信件、安静离开 |
| 环境只有程序噪声 | 建立随地点和身体状态变化的声音层 |

## 2. 迭代原则

1. 每轮只验证一个核心假设，不同时铺开所有内容。
2. 先用灰盒和临时素材验证行走、拍照、时间推进和情绪节奏，再批量生成美术。
3. 任何新系统必须直接服务“年轻女孩的一次冒险”；不能解释清楚其情绪功能的系统不加入。
4. 每个阶段都保持可从头运行到当前结尾，不留下无法试玩的中间状态。
5. 每次线上更新保留版本标签和简短试玩问卷。

## 3. 阶段计划

### 阶段 0：设计冻结与代码基线

状态：当前阶段。

工作：

- 将设计锁定和迭代计划提交仓库。
- 给现有版本打 `prototype-v0` 标记。
- 保留线上旧版用于前后对比，不在其结构上继续堆功能。

验收：团队对“角色化第一人称 2.5D 旅行冒险”没有不同解释。

### 阶段 1：新体验骨架

状态：**第二版已实现，等待“是否像游戏”试玩验收。**

目标：证明 2.5D 第一人称不再像幻灯片。

工作：

- 引入 PixiJS 渲染层。
- 建立数据驱动的章节 / 场景状态机。
- 完成一个三层视差山路灰盒。
- 实现有限环视、点击目标后的连续前进、回头和遮挡转场。
- 实现严格无身体入镜的第一人称镜头，并用物体、镜头和声音反馈动作。
- 保留 React 手机 UI，并与场景状态双向通信。
- 删除悬浮玩法按钮：行走改为点击场景中的目的地后自动走近，选路改为直接点击空间路线，过溪改为直接操作落脚石，背包改为可拖动物件。
- 旁白自动出现且不阻断操作，不再点击翻页。

交付切片：下车点 → 山路入口 → 第一个观景点，约 5 分钟。

验收：

- 玩家能描述自己“走到”观景点，而不是“点击切到”观景点。
- 玩家能从手机、随身物、聊天和声音判断主角是年轻女性，同时不被预设外形阻碍代入。
- 没有使用剧情文字也能理解路线关系。
- 玩家描述的是自己执行了动作，而不是按按钮观看动作发生。

### 阶段 2：冒险乐趣垂直切片

状态：**已接入主线并通过场景级视觉走查，等待真人节奏试玩。**

目标：在没有危险和命运内容时，游戏本身仍然好玩、好看、想继续走。

工作：

- 完成观察目标 → 选择靠近 → 轻量通过 → 得到风景的核心循环。
- 制作两种地形交互：铁索通过、碎石坡落脚。
- 实现回望已走路线。
- 实现真实构图截图与相册保存。
- 加入人物生活化自言自语、手机壳、锁屏和少量旧照片。
- 建立时间随探索、绕路和失败自然推进的规则。

交付切片：山路入口 → 两段通过 → 高处风景 → 发现并拍下信件，约 12–15 分钟。

验收：

- 至少 70% 的测试者在没有任务要求时主动拍摄两张以上照片。
- 玩家首先把体验称为“旅行 / 冒险”，而不是叙事点击游戏。
- 玩家喜欢主角的陪伴感，但不觉得她说话过多。
- 信件不会让多数玩家提前判断游戏是灵异或解谜题材。

### 阶段 3：危险认知与自救

状态：**八步夜路、光源、电量、呼吸和手机遗失已接入主线。**

目标：让同一座山从美丽自然地转化为危险，同时保留主角主动性。

工作：

- 制作实时光线从下午到日落的变化。
- 让玩家主动打开地图、时间和电量后意识到处境。
- 制作夜间手电、路线搜索、滑倒与恢复。
- 用呼吸、脚步、镜头和自言自语表现恐惧，不加入怪物。
- 实现手机在摔倒后无提示遗失，直到安全后摸口袋才被发现。

交付切片：高处平台 → 察觉危险 → 夜间下山 → 抵达公路，约 10–12 分钟。

验收：

- 玩家能指出是自己的探索时间和路线判断形成了危险。
- 玩家感到害怕，但不把游戏识别为恐怖游戏。
- 玩家认为自己完成了自救，而不是等待剧情救援。
- 手机丢失的发现无需文字提示也能被理解。

### 阶段 4：普通人的温度

状态：**公路车辆、两位救援者独立层、车内恢复与共同寻机已完成。**

目标：让陌生人的帮助成为现实层面的情感核心。

工作：

- 设计两位救援者 / 新朋友的性格、关系和对话节奏。
- 制作公路求助与判断是否信任的轻交互。
- 制作车内暖风、递水、松弛和恢复说笑的段落。
- 制作共同返回搜索：慢速行车、观察路面、下车寻找、借手机拨号。
- 让重复搜索同时推进人物关系，避免任务化刷点。

交付切片：公路获救 → 车内交流 → 返回寻找 → 确认找不到，约 10–12 分钟。

验收：

- 玩家记得两位帮助者的性格，而不只记得“NPC救了我”。
- 玩家认为他们成为朋友是自然发生的。
- 找不到手机带来真实遗憾，但没有压倒冒险整体的温暖。

### 阶段 5：接受、归还与余韵

状态：**普通路人归还、相册恢复、离谷回看与单一结尾已完成。**

目标：让最后的奇妙来自无法解释的普通巧合，而不是悬疑揭晓。

工作：

- 制作主角主动安慰自己并接受损失的安静段落。
- 设计手机被普通地递回视野的第一人称动作，不显示主角身体。
- 恢复玩家自己拍摄的全部照片。
- 让玩家在相册里自然重新看到信件。
- 删除解释命运的结尾旁白，仅保留极少反应和离开山谷的声音 / 画面。

交付：从放弃寻找到完整结局，约 4–5 分钟。

验收：

- 玩家描述手机归还为“巧”“幸运”“世界很温柔”，而不是超自然。
- 多数玩家会在相册中停留并回看自己的旅行照片。
- 玩家在没有解释的情况下自行把信件与经历联系起来。

### 阶段 6：完整内容、美术与声音统一

状态：**功能与资源整合已完成：14 节点、主要场景板、独立物件、声音分层、WebP 压缩与首屏拆包均已接入；等待真人节奏与多设备放行。**

目标：把验证通过的灰盒扩展为 35–50 分钟完整短篇。

工作：

- 按统一角色和环境参考使用 GPT Image 制作 12–14 张场景板。
- 为每张主场景拆分前景、中景、远景和动画元素。
- 完成手机、背包、挂件和 UI 的一致性资产；全程检查主角身体不入镜。
- 完成环境声音、身体声音、车辆和手机声音。
- 增加章节存档、继续游戏、字幕和减少动态选项。
- 优化 WebP、纹理尺寸、首屏加载和低端设备性能。

验收：

- 完整游玩时长中位数 35–50 分钟。
- 首次加载与场景切换无明显阻塞。
- 所有场景中身份物件和手机视觉一致，且不存在身体、影子或倒影露出。
- 不依赖临时文字说明完成故事理解。

### 阶段 7：三轮定向试玩

#### A 轮：形式验证（5–8 人）

只测试前 15 分钟。验证它是否首先被感知为一次年轻女孩的旅行冒险。

#### B 轮：情绪验证（8–12 人）

测试完整灰盒。记录危险意识、获救、放弃和归还四个节点的口述反应。

#### C 轮：陌生玩家验证（15–30 人）

不提供主题说明，只给出游戏下载链接。通过问卷确认玩家是否自行产生“被世界善待”的表达。

最终放行标准：

- 80% 以上玩家首先将作品描述为旅行 / 冒险。
- 70% 以上玩家能描述主角的年龄感和两个以上性格特征。
- 70% 以上玩家在手机归还时使用“巧、幸运、温暖、奇妙”中的至少一种近义表达。
- 少于 15% 的玩家把事件解释为明确超自然现象。
- 少于 15% 的玩家认为前半段只是为后续剧情服务的冗长铺垫。

## 4. 推荐执行顺序

不要立即重做完整剧情。下一次开发只执行阶段 1，并以 5 分钟新切片替换当前 Demo 的开场。阶段 1 未通过“走到而非点到”的验证前，不生成后续批量美术，也不制作救援和结局。

阶段 2 是项目的生死检查点：如果没有危险、手机丢失和命运结尾时，玩家仍不享受与她一起探索，说明主体体验尚未成立，必须继续修改冒险循环，而不能依靠后半段剧情补救。
